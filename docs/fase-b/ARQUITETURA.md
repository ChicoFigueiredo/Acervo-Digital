# Arquitetura e plano de engenharia

## Gate 0 — investigação obrigatória antes de codificar
Auditar main atual e ADRs, schema, APIs do agente, hashes, scanner de compactados, MCP e lixeira. Estudar upstream https://github.com/kovidgoyal/calibre e https://manual.calibre-ebook.com/ (fixar commit e versão instalada). Mapear código de metadata, db/cache/backend, field metadata, custom columns, ebooks/metadata, plugins, conversão, CLI calibredb, ebook-meta e mecanismos de bibliotecas/servidor. Inspecionar também https://github.com/ChicoFigueiredo/calibre-port. Entregar matriz campo Calibre → tipo/cardinalidade → leitura/escrita suportada → evidência upstream → teste; incluir campos não graváveis e derivados. Não presumir que lista deste documento é exaustiva. Ler biblioteca pessoal local somente com autorização; exportar perfil anonimizado, nunca dados reais ao GitHub.

## Integração
Usar APIs/CLI suportadas conforme versão (calibredb list, add, add_format, set_metadata, export e clone de estrutura quando disponível; ebook-meta para leitura). Validar capacidades reais e concorrência com GUI/servidor; coordenar escrita pelo mecanismo suportado. SQLite do Calibre é referência de estudo, não contrato público de escrita. Não editar metadata.db diretamente. Snapshot consistente para análise quando necessário. Duas bibliotecas físicas independentes, IDs próprios, mapeamento persistente DAG↔Calibre. Verificar round-trip e idempotência, não sobrescrever formatos. Proteger raízes de biblioteca contra lixeira e loops de ingestão. Registrar alterações externas.

## Pipeline
Inventário existente → fila por tamanho/benefício → hash e match exato → extração nativa → OCR seletivo/layout → evidências → classificação IA → validação determinística → resolução de obra/edição/formato → staging Calibre → revisão → promoção → backup verificado → candidatos à limpeza. Evitar OCR repetido de hashes idênticos; cache por hash, versão extrator/modelo/prompt e política. Reprocessar somente etapas invalidadas. Eventos novos usam fila incremental com debounce e reconciliação. Um escritor DAG, transações curtas e operações Calibre com journal/outbox, recuperação e verificação após falha.

## Componentes sugeridos (adaptar aos crates existentes)
Extratores ebooks, OCR, bibliografia, adaptador Calibre, provedores IA, similaridade e orquestração. Contratos de jobs e eventos; UI Ribbon Biblioteca/Curadoria/Monitoramento; CLI e MCP com leitura por padrão e ações mutáveis explicitamente autorizadas. Entidades: fonte, membro de arquivo, obra, edição, exemplar/formato, evidência de campo, sugestão, taxonomia, correção, job, vínculo Calibre, candidato a descarte, manifesto backup. Não duplicar inventário.

## Modelos locais e benchmark
Pesquisar Hugging Face, model card oficial, licença, arquitetura e compatibilidade real de Inkling 2 Mini; verificar se nome está correto. Não assumir que GGUF existe. GGUF é formato de distribuição, não garantia de compatibilidade multimodal. Avaliar quantizações Q4/Q5 ou equivalentes, runtime llama.cpp ou alternativa compatível, projetor visual quando necessário, contexto/KV cache e pico real de VRAM. GPU 16 GiB: meta proposta pico ≤14,5 GiB em execução normal, sem OOM, ajustar contexto/lote/offload; não exigir dois modelos residentes. Registrar GPU/driver, runtime, revisão do modelo, checksum, licença, quantização, tokens/s, páginas/min, VRAM/RAM e acurácia. Comparar pelo menos dois candidatos locais com conjunto ouro do proprietário; se Inkling indisponível/incompatível, registrar evidência e propor alternativa. OCR especializado (Tesseract/PaddleOCR ou equivalente) + modelo bibliotecário; segundo LLM opcional para divergências. Saída JSON validada, evidências por campo, abstinência, sem executar instruções encontradas nos documentos. Nenhuma API paga/remota sem consentimento.

## Segurança
Sandbox de parsers/OCR, limites de descompressão, profundidade, páginas, tempo, memória, proteção contra path traversal e symlinks; arquivos temporários privados e limpeza. Não executar scripts de EPUB/PDF. Revalidar identidade e hash antes de movimentar; revisar TOCTOU, recuperação entre rename e SQLite, proteção contra cópia única. Similaridade nunca autoriza descarte. Backup verificável e restauração isolada; sem purga enquanto não verificado.

## Incrementos
0 investigação e perfil; 1 integração e staging; 2 extratores/OCR; 3 benchmark IA e aprendizado; 4 matching e vigilância; 5 revisão/promoção/backup/limpeza; 6 testes reais Linux e documentação. Cada incremento entrega evidências e não declara funcionalidades futuras prontas.
